# v1.1.10

发布日期：2026-09-15

## 版本说明

本版本完成 GPT 邮箱资源池的真实数据接入：当前可将本地 HME 全量同步到独立资源池，并为后续协议注册器和浏览器注册器提供安全、来源无关的邮箱领取与验证码接口。

## 新增

- 新增独立邮箱资源池，以 `source_type` 和稳定来源引用管理邮箱；当前支持本地 HME，数据模型保留未来扩展其他邮箱来源的能力。
- 新增邮箱资源列表、服务端分页与筛选、HME 全量同步，以及来源适配器提供的一条可空验证码。
- 新增执行器邮箱占用接口：原子领取、心跳续期、本次占用后的验证码读取、成功确认、失败释放和超时回收。
- 新增 Alembic `20260915_0029`～`20260915_0031`，建立邮箱资源、持久占用关系并修复旧状态映射。

## 优化

- 邮箱池页面改为真实 API 纯列表，移除用途标签、使用次数、ChatGPT 绑定、最近收件、最近同步、详情和手工状态操作。
- HME 同步前明确二次确认全部未同步资源范围；同步成功后立即回到第一页并刷新主列表。
- HME 别名库存状态不再被误当作邮箱池使用状态：非禁用 HME 首次进入资源池均为“可用”，只有自动化执行器完整成功后才标记“已使用”。

## 安全与可靠性

- PostgreSQL 行锁、活动占用唯一约束和 holder 幂等键共同防止邮箱被重复领取。
- 注册失败、取消、执行器停止、验证码超时或租期过期时，邮箱自动恢复为“可用”。
- 验证码只允许当前占用者读取，并过滤占用开始前的旧邮件；验证码不写入资源表、占用表、日志、审计或幂等快照。
- `20260915_0031` 只修复没有成功注册历史的旧误映射 HME，不覆盖真实成功结果和其他来源。

## 数据库迁移

- 升级前备份 PostgreSQL。
- 运行 `alembic -c backend/alembic.ini upgrade head`，目标 head 为 `20260915_0031`。
- `0031` 的降级不会反向恢复错误的“已使用”状态，修正后的业务数据会安全保留。

## 验证

- 后端完整测试：905 passed、49 skipped，覆盖率 83.01%。
- PostgreSQL 隔离迁移、状态修复、并发领取与占用生命周期测试通过。
- Ruff、mypy 152 个源文件、Alembic 单一 head、版本一致性、全部前端专项、TypeScript/Vite 构建和敏感信息扫描通过。

## 升级步骤

1. 备份 PostgreSQL，并保留现有 JWT/AES 密钥。
2. 拉取 `v1.1.10`，重新构建应用镜像。
3. 先执行 Alembic 迁移到 `20260915_0031`，再启动 API 与 Worker。
4. 检查 `/api/v1/health/ready`，登录邮箱池页面并确认 HME 资源状态为“可用”。
5. 执行一次“HME 同步”，确认二次确认、同步结果和主列表刷新正常。
