# v1.1.7

发布日期：2026-09-14

## 版本说明

本版本重构运行配置体系：除数据库、JWT、AES 密钥、统一客户端模式和 Mihomo Secret 等部署边界外，其余运行参数全部进入 PostgreSQL 通用配置表，并修复 Playwright CK 采集过早完成的问题。

## 新增

- 新增通用键值表 `system_configs`，按稳定键保存 51 项运行参数及名称、类型、分类、校验规则、可编辑性、重启要求和乐观锁版本。
- 系统设置页面根据后端元数据动态分组渲染，支持逐项更新与版本冲突检测。
- 新增 CK 采集完成条件回归测试，并纳入统一发布门禁。

## 优化

- 部署环境只保留 PostgreSQL 连接、JWT 签名密钥、AES 主密钥与轮换版本、统一客户端模式和 Mihomo Secret；可选数据库连接参数仍属于部署边界。
- HME、IMAP、代理探测、订阅抓取和 Mihomo Controller 统一读取 `MAILFORGE_CLIENT_MODE=mock|live`。
- API 和 Worker 启动时从数据库加载完整配置，对缺失键、类型错误、越界和跨字段冲突立即拒绝启动。
- Compose 不再内嵌运行参数，只通过 `env_file` 加载部署环境。
- 前端活动默认值、接入指南和通知开关直接读取数据库配置，不再使用硬编码业务兜底。

## 修复

- CK Bridge 与 Playwright CLI 不再把 `X-APPLE-WEBAUTH-USER` 等预登录 Cookie 当作完整会话。
- 只有检测到 `X-APPLE-DS-WEB-SESSION-TOKEN` 后才结束采集，避免生成格式正确但被 iCloud 返回 401 的 CK。

## 数据库迁移

- 新增 Alembic `20260914_0024`，创建 `system_configs`、迁移旧 `app_settings` 的 15 项已有值、补齐注册表默认项，随后删除旧宽表。
- 降级会恢复旧表、字段类型与约束；升级、降级和重新升级已经在 PostgreSQL 隔离 schema 中验证。
- 升级前必须备份 PostgreSQL，并先执行迁移再启动 API 与 Worker；升级后的唯一 head 为 `20260914_0024`。

## 不兼容变更

- 本版本不兼容旧的分模块运行参数环境变量。部署前必须按新版 `.env.production.example` 收敛环境文件。
- 真实 iCloud、IMAP、订阅和代理能力统一要求 `MAILFORGE_CLIENT_MODE=live`；本地 Mock 验证统一使用 `mock`。
- 非本机 Mihomo Controller 在 Live 模式下必须配置真实 `PROXY_MIHOMO_SECRET`，否则 API 和 Worker 会拒绝启动。

## 验证

- 后端完整测试：944 passed、42 skipped，覆盖率 80.01%。
- CK 采集回归：3 passed；真实 Playwright 采集取得 iCloud Web Session Token，Live CK 更新与恢复校验通过。
- Ruff、mypy 155 个源文件、Alembic head、版本一致性、前端回归、TypeScript/Vite 构建和敏感信息扫描全部通过。

## 升级步骤

1. 备份现有 PostgreSQL，并保存当前 JWT/AES 密钥；不可轮换或丢失已有 AES 密钥。
2. 以源码仓库新版 `.env.production.example` 为准更新部署环境，设置统一客户端模式与 Mihomo Secret。
3. 拉取 `v1.1.7`，重新构建镜像并运行 `migrate` 服务执行 `alembic upgrade head`。
4. 迁移成功后重建 API 与 Worker，检查 `/api/v1/health/ready`、Worker 日志和系统设置页面。
5. Live 部署重新校验 iCloud CK、IMAP 和 Mihomo Controller；CK 已修复但账户仍为管理员暂停时，需要执行“恢复”。
